# 从第一次连接到查看候选

在 Codex 中说出目标即可，不需要自己写配置、JSON 决策或运行命令。Codex 根据本 skill 操作服务器，并把进度、结果和下一步解释给你。

**Mac／Windows 上只需 Codex、skill 和 SSH 连接。** Python、设计工具、模型权重、输入数据与结果都在远程 Linux 服务器；本机无需 Python、WSL 或 CUDA。默认只向你展示摘要，完整文件留在服务器。

## 能做什么

| 你想做的事 | Codex 会做什么 | 你会得到什么 |
| --- | --- | --- |
| 确认服务器能否使用 | 检查连接、调度器、环境、工具版本、权重与路径 | 已通过项、缺项、明确的下一步 |
| 补齐设计环境 | 复用兼容安装，为缺失或不兼容组件配置独立环境 | 可用路径、版本与检查报告 |
| 准备一个靶标 | 检查结构与链编号，结合你提供的约束生成运行配置 | 靶标检查结果、设计范围与预算 |
| 先试跑，再正式设计 | 在已授权 GPU 资源内调用后端，按中间结果规划后续动作 | 作业状态、日志、候选与停止原因 |
| 查看或调整任务 | 解释进展与失败原因，检查是否可以恢复或需新建任务 | 当前阶段、已用预算、后续建议 |
| 检查并导出候选 | 汇总计算筛选结果、结构/序列聚类标注并导出 | 候选清单、PDB 文件及服务器路径 |

内置工作流程直接调用后端，不需要另装 T-REX。BindCraft、BoltzGen、Complexa 等科学工具仍需部署在服务器，skill 没有一键安装所有后端和权重的安装器。

## 第一次使用，按这六步走

| 阶段 | 可以直接对 Codex 说 | 这一步真正需要你补充什么 |
| --- | --- | --- |
| 1. 连接与清点 | “用 trex-binder-design 检查我的远程 GPU 设计环境，先告诉我哪些已可用、缺什么。” | 尚未确认的 SSH 别名或连接信息；不要把私钥或密码粘进对话 |
| 2. 补齐环境 | “沿用刚才的连接，按最小流程补齐环境，在独立目录配置兼容组件，复用核验通过的权重。” | 若无法从现有配置确定：可写工作目录、软件安装或下载限制 |
| 3. 准备靶标 | “我要为这个靶标设计 binder。先检查服务器上的结构，再帮我整理设计约束，只问还缺的信息。” | 靶标身份、研究目的、结构的服务器路径、目标链与约束；热点等未确定项明确说明未确定 |
| 4. 小规模验收 | “使用刚确认的靶标和配置，在我给定的 GPU 数量与时限内做一次小规模验收，检查设计、复评、归档和停止是否正常。” | 尚未确定的 GPU 数量、时限及调度配置；Codex 会先说明本次测试范围 |
| 5. 正式设计 | “沿用验收通过的环境和靶标，按这个计算预算开展正式设计，持续检查并汇报进展。” | 本次计算预算及希望达到的筛选/候选目标；数量目标不代表保证产出 |
| 6. 分析与导出 | “汇总这次任务的结果，解释筛选与聚类情况，导出最多 20 个候选到服务器，并告诉我文件位置。” | 多个任务时指定哪一个；有特殊筛选或导出要求再补充 |

已经提供过的连接、路径、靶标和授权继续沿用。每个阶段只收集阻塞下一步的缺项，不要求一次填完整套表单；Codex 负责生成和检查配置。

准备约束时会检查后端是否支持。当前可处理目标链、热点；禁结合面、实验几何和成药性过滤尚未实现，填写相关非空字段会停止检查并说明原因，不能把“配置已保存”当作“约束已执行”。

环境配置与真实 GPU 运行是两个阶段。仅检查或补齐环境时不启动设计；你已明确给出运行范围、预算和资源后，Codex 按授权推进，不再反复询问相同事项。

“小规模验收”表示限制 GPU 数量、总时限和单批运行时限，不保证几分钟完成。Codex 会将首轮合法配置落实到实际候选，并为复评预留时间。后端的候选数量目标是通过筛选的配额，失败尝试可能继续；单批时限负责结束该批计算，到预算上限仍可能没有合格候选。

要按自适应循环运行，可以直接说：

> 沿用已经确认的靶标、服务器和预算，按自适应循环设计：先做一批并独立复评，再根据结果调整策略继续下一批，直到达到预算或我要求停止。报告实际采用的设置和每次调整依据。

不需要指定工具名称或手写参数。Codex 会根据已启用且检查通过的后端选择合法动作；科学工具和约束尚未就绪时，会先解释缺项。完整循环包括新一批实际设计、复评和再次决策，不能只看到“计划已接受”就算完成。

## 已经检查完，但版本不匹配或缺环境：下一步是什么

这表示“服务器已连通，环境尚待补齐”。你可以直接说：

> 沿用刚才的检查结果，先配置 BindCraft → 独立 AF2 复评 → Foldseek/MMseqs2 聚类这条最小流程。为缺失或版本不兼容的组件建立独立目录和环境，复用核验通过的权重。先完成不消耗 GPU 的检查，再告诉我试跑还缺哪些信息。

Codex 随后应完成这些具体工作：

1. **控制器环境**：为本 skill 的执行代码准备服务器 Python 3.12 环境。它与设计后端的 Python 环境分开；发现系统 Python 3.10，不代表已有 BindCraft 环境必须重装。
2. **BindCraft 兼容性**：核对源码版本、所需改动、依赖和权重。现有安装不匹配时，在独立目录准备兼容副本，保留实验室原安装，不通过关闭检查来“通过验收”。
3. **独立 AF2 复评**：检查复评代码、环境与参数文件。BindCraft 自身能评分，不等于 skill 使用的独立复评入口已经可用。
4. **聚类工具**：检查服务器上的 Foldseek 与 MMseqs2 可执行文件及兼容性，用于候选结构/序列聚类标注。
5. **汇报就绪程度**：说明哪些项已验证、哪些仍未验证，给出下一条可直接使用的指令。靶标已提供时继续生成配置并检查；尚未提供时只收集准备试跑所需的靶标信息。

这条最小流程可以暂不启用 BoltzGen、Complexa 生成和独立的 ProteinMPNN 重设计动作。BindCraft 自身所需的依赖与权重仍要齐全；AF2 复评也需要兼容的代码和权重。以后需要更多设计方法时再配置相应组件。

**发现目录或权重文件，不等于确认可用。** 文件完整性与版本检查、环境加载检查、真实 GPU 推理验收应分别报告。只有实际完成的步骤才能标记为通过。

## 运行期间怎么用

你可以继续用自然语言操作：

- “现在进行到哪一步了？有多少任务完成、多少失败，还剩哪些检查？”
- “解释这次失败原因，先检查日志和环境，不扩大计算预算。”
- “停止新增任务，让正在运行的任务正常收尾，并报告最终状态。”
- “不再生成新候选，把已有候选的独立 AF2 复评做完，再导出结果；列出未完成的项目和原因。”
- “上次中断后还能恢复吗？先核对旧作业是否已结束、输入和代码是否一致。”
- “这些候选分别通过了哪些计算筛选？有哪些指标缺失？”
- “把刚才导出的清单和 PDB 下载到我指定的本地目录。”

**本版需要当前 Codex 会话持续参与运行。** 每次决策请求默认留出 15 分钟，由 Codex 完整读取证据并响应，用户不需要手工答复；实际期限受剩余任务时间约束。等待期间继续监督已有设计任务，但不启动新后端。关闭会话或中断响应后，不能保证任务持续自主推进；超时会停止新增调度并收尾，已有 GPU 进程不一定立即结束。任务时长的硬限制由服务器调度器保证。

计算筛选通过不等于已经获得有效 binder，也不等于实验亲和力或特异性。导出提供候选清单与 PDB；不自动生成 FASTA。聚类标注不能保证排除所有重复结构。
